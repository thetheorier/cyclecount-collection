# iPhone Battery Capacity & Cycle Count Dataset

iPhoneの「最大容量（Maximum Capacity）」と「サイクル数（Cycle Count）」を、公開されている実例から収集・整理するためのデータセットです。

目的は、「○年使って最大容量○%」のような個別の体験談を多数集め、最大容量とサイクル数の関係を統計的に調べることです。

Dataset

battery_data.csv

1行を1つの観測データとして扱います。

Column	Description
id	レコードを識別するための固定連番
model	iPhoneのモデル名
capacity	最大容量（%）
cycles	サイクル数（Cycle Count）
source	データの掲載元
source_url	データを確認したWebページのURL
note	補足情報

id は単なるレコード識別子です。データの意味を表すものではなく、行の並べ替えや削除があっても既存レコードを識別するために使用します。

Collection Rules

採用するデータ

以下を満たす実例を採用します。

1. Maximum Capacity（最大容量）と Cycle Count（サイクル数）の両方が確認できること
2. 数値が明確に読み取れること
3. iPhoneのバッテリー状態を示す実測値であること
4. 公開Webページ上で確認でき、出典URLを記録できること
5. 同じ観測結果を重複して登録していないこと

最大容量とサイクル数のどちらか一方しか確認できない投稿は採用しません。

原則として除外するデータ

* 最大容量またはCycle Countが不明なもの
* 数値を推測・計算して補ったもの
* 画像から数値を確認できないもの
* iPhone以外のデバイス
* 中古販売ページなど、所有者本人の使用状況を示す実測データではないもの
* 同じ投稿・同じ画像の重複
* 明らかに同一の観測結果を別ページから転載したもの
* バッテリー容量についての推測値や一般論のみを記載したもの

Duplicate Handling

同じ「最大容量＋Cycle Count」だからといって、自動的に重複とはしません。

例えば、

* iPhone 15 Pro / 95% / 400 cycles / MacRumors
* iPhone 15 Pro / 95% / 400 cycles / Reddit

は、別の観測結果である可能性があるため、別レコードとして扱います。

重複判定では、可能な範囲で以下を確認します。

* 投稿内容
* 画像
* モデル
* 最大容量
* Cycle Count
* 出典
* source_url

同一人物・同一端末による複数時点の報告については、同じ端末の経過観測を大量に登録してサンプルを水増ししないよう注意します。

Source URL

source_url は、そのレコードの数値を確認したWebページのURLを記録します。

同じページから複数のレコードを採用することは可能です。

source_url に既に登場しているURLは、原則として調査済みページとして扱い、同じページを繰り返し調査しないようにします。

ただし、採用データが0件だった調査済みURLは battery_data.csv の source_url には残りません。

必要になった場合は、将来的に searched_urls.csv を追加して管理します。

Search Strategy

効率よくデータを収集するため、検索結果を1件ずつランダムに拾うだけでなく、関連するスレッドやページを見つけた場合はページ単位で総ざらいする方式を優先します。

特に、

* MacRumors
* Reddit
* その他、最大容量とCycle Countの実例がまとまっている公開サイト

などを対象とします。

同一スレッドでは複数ページを確認し、既に調査したページを再調査しないよう source_url を利用します。

Statistical Use

このデータセットは、個々のユーザーに対するバッテリー状態の診断を目的とするものではありません。

主な分析対象は、

* 最大容量ごとのCycle Count分布
* Cycle Countごとの最大容量分布
* 最大容量 100%、99%、98%……などのグループ別統計
* 機種ごとの傾向
* 最大容量とCycle Countの関係

などです。

特に、全データを一括して平均するだけではなく、最大容量の値ごとにサンプルを分けて確認することを重視します。

Sample Size

初期目標は 500件です。

500件を超えても、統計的な安定性や容量別サンプル数を増やすため、収集は継続します。

現在はさらに 1,000件以上、可能であれば2,000件程度までサンプルを増やすことを目標としています。

Progress Tracking

調査中は以下の形式で進捗を管理します。

現在：n = xxx / 500
連続0件：x / 5

* n = 採用済みの観測データ数
* /500 = 当初の目標件数
* 連続0件 = 検索を行っても新規採用データが見つからなかった連続回数

5回連続で新規データが見つからない場合は、検索対象・検索方法・検索サイトなどを見直します。

Important Notes

このデータセットは、公開Web上で収集した自己申告・投稿ベースの観測データです。

そのため、

* 投稿者や端末の使用条件は統一されていない
* 充電方法・温度・使用時間などの条件は一定ではない
* 同一モデルでも個体差がある
* 投稿されるデータには選択バイアスがある可能性がある

といった制約があります。

したがって、統計結果は「一般的なiPhoneユーザー全体の厳密な代表値」ではなく、公開されている実例から見た傾向として扱います。

Continuation Across Chats

このCSVをマスターデータとして扱います。

チャットの上限などで調査を別チャットへ移す場合は、最新の battery_data.csv を基準にします。

新しいチャットでは、

1. battery_data.csv を確認
2. 既存の id と source_url を確認
3. 既存データとの重複を避ける
4. 未調査のページを検索
5. 新規データを追加
6. n を更新

という手順で調査を再開します。

チャットの会話履歴ではなく、このCSVをデータセットの正本（source of truth）とします。
